# 農曆查詢：保留文字，不猜國曆日期

服務支援農曆主題與文字搜尋，不提供農曆日期換算。農曆期間保存在
`SearchState.unapplied_time`，並在介面標示未套用日期篩選。

| 輸入 | 行為 |
|---|---|
| 農曆文化研究、國農曆對照表 | 當作研究主題，不因包含農曆字眼攔截。 |
| 農曆三月的交通資料 | 搜尋交通與原始農曆文字，不套用模型猜測的國曆日期。 |
| 從 2024 年水質 CSV 改成農曆區間 | 保留水質及 CSV，移除舊日期，改存未套用的農曆文字。 |
| 接著只要 PDF | 只改格式，保留農曆文字與提示。 |
| 補充完整國曆日期／起訖範圍 | 套用國曆條件，清除農曆文字與提示。 |
| 取消時間限制或明確換題 | 清除原農曆期間。 |

## 狀態與驗證

```json
{
  "topic": "交通",
  "time": null,
  "formats": ["CSV"],
  "unapplied_time": {"calendar": "lunar", "text": "農曆三月"}
}
```

`time` 與 `unapplied_time` 不能同時非空。農曆文字只參與文字／語意檢索，不傳入
metadata 日期篩選。它必須是本輪或待澄清問題的原文片段，最多 128 字元。
明確農曆日期若被模型輸出為國曆區間，程式拒絕該計畫並保留原狀態。

不支援的日期不等於惡意輸入；用途與安全檢查仍先執行，缺少主題時仍可澄清。
農曆文字不能混進永久 topic，否則使用者補國曆日期後會留下錯誤限制。

搜尋結果可能為空，也不能保證找齊符合該農曆期間的資料。介面須持續顯示
「僅文字搜尋」與未套用日期的提示，不能讓格式追問看起來已完成換算。

型別與執行規則見 [conversation contract](../search/api/conversation/contract.py)
及 conversation engine。修改時檢查 `search/tests/test_conversation*.py`
與 `make search-web-ci`，涵蓋主題誤擋、日期替換、格式追問及國曆補充。
