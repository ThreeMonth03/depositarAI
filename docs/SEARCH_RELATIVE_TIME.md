# 相對日期：理解與運算分開

LLM 辨識使用者引用的相對期間，程式驗證後計算絕對日期。相關來源位於
`search/api/conversation/time.py` 與 conversation engine；API clock 契約見
[私有 API](API.md)。

```text
「找最近三年水質資料」
  → 模型選取原文片語，輸出 rolling / year / 3
  → 程式驗證文字、種類、單位、數量與參考時間
  → 計算絕對區間 → 檢索、篩選及排序
```

## 日期慣例

| 類型 | 例子 | 計算 |
|---|---|---|
| rolling | 最近三年、過去一個月 | 從參考日向前推 N 年／月；無效月底夾到當月末日。 |
| rolling | 過去 N 天／N 週 | 含今天，共 N 天／7N 天。 |
| calendar | 去年、今年、上個月、上週、昨天 | 完整曆年／月／週／日；一週為週一至週日。 |
| to_date | 今年截至今天、本月至今 | 本期第一天至參考日。 |

起訖日皆 inclusive，套用到資料涵蓋期間。「最近一年」、「去年」與「今年截至
今天」有不同範圍；介面顯示實際日期，讓使用者確認。

## 驗證與多輪行為

唯一錨點是經驗證的 `context.reference_time` 與 IANA `timezone`。BFF 每輪提供
當下 UTC 時間；沒有 clock 時要求澄清，不偷用模型訓練日期或主機時間。

模型引用的片語必須來自本輪輸入。原文「三」卻輸出 2、錯誤單位／種類、複合
期間或不完整引用都不能執行。生成 schema 將可選文字限制在本輪偵測到的片語，
engine 仍做最終驗證，不能只信任生成格式。

「最近三年半」等未支援修飾不截掉後半後近似搜尋。支援文法是封閉集合，
未知表達仍可能有語意辨識風險；不宣稱完整理解任意自然語言。

Session 保存解析後的絕對日期。下一輪只改 CSV，即使 clock 跨年也不滑動舊期間；
明確重新說「去年」才重新解析。舊 pending 的相對片語不能覆蓋新主題。
農曆依[文字搜尋規則](SEARCH_LUNAR_TEXT_SEARCH.md)處理，不使用國曆計算器換算。

修改時以 `search/tests/test_conversation_time.py` 及相關 conversation tests 檢查
跨年、閏年、月底、時區、缺少 clock、格式追問及取消限制；網站流程另跑
`make search-web-ci`。日期正確性與檢索相關性分開評估。
