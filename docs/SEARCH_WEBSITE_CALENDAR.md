# 日期、紀年與澄清

日期處理位於 `search/api/conversation/calendar.py`。它負責可確定的紀年轉換與
輸入檢查；條件規劃仍由 conversation engine 協調。操作方式見
[搜尋指南](guide/using-search.md)，相對期間與農曆另見
[相對日期](SEARCH_RELATIVE_TIME.md)、[農曆文字搜尋](SEARCH_LUNAR_TEXT_SEARCH.md)。

## 紀年規則

| 輸入 | 行為 |
|---|---|
| 111 年的澎湖古蹟資料 | 先詢問民國或西元，不猜測紀年。 |
| 民國 111 年／民國一百一十一年 | 加 1911 轉成 2022 年，回應附換算提示。 |
| 西元 111 年 | 保留西元 0111 年。 |
| 民國 113 年 2 月 29 日 | 驗證閏日並轉成 2024-02-29。 |
| 民國 111 年 2 月 29 日 | 日期無效，澄清並保留上一輪條件。 |
| 最近三年 | 使用相對時間規則，不當成民國三年。 |

民國／西元是紀年；農曆／國曆是曆法。明寫民國而沒有農曆標示的月日按國曆
處理，不能據此宣稱支援農曆換算。

## 保留語意與狀態

單一且沒有範圍或排除語意的確定日期，可由程式提供區間。多日期、以前／以後、
季度、半年度及取消限制交回 planner；不能只擷取其中一年而覆蓋整句語意。

用途及輸入檢查仍看原始問句。澄清不改既有狀態；使用者補上明確紀年或國曆日期
時，只在 planner 的輸入副本替換已更正的待澄清日期，保留主題、格式及其他條件。
未辨識的複雜範圍不做替換，可請使用者重述完整需求。

格式操作區分 `keep`、`clear` 與包含 1–4 個白名單值的清單；空陣列不能同時表示
「保留」與「清除」。沒有已提交主題時，不允許模型直接 refine 空狀態。

時間比對資料涵蓋期間，不是 metadata 修改日。日期未知的資料會保留標記；
日期解析成功也不代表每張卡片都有符合期間的證據。此服務不是學年度、會計年度、
歷史年號或任意曆法的完整解析器。

修改規則時檢查 `search/tests/test_conversation*.py` 與 `make search-web-ci`，
涵蓋紀年澄清、閏日、格式保留及多輪日期替換。實際模型品質另以固定問句評估。
